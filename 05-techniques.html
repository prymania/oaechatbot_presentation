หัวข้อที่ 5 · เทคนิคขั้นสูง

เทคนิคที่ยกระดับความแม่นยำและป้องกันการตอบข้อมูลเท็จ

ระบบจริงเพิ่มอีก 9 ขั้นตอนรอบการค้นคืนพื้นฐาน เพื่อให้ได้คำตอบที่ตรงประเด็น มีลำดับความน่าเชื่อถือ และ "กล้าปฏิเสธ" เมื่อไม่มีข้อมูลรองรับ

5.1Pipeline เต็มรูปแบบ ณ เวลาที่ผู้ใช้ถามคำถาม

5.2Reranking — จัดลำดับความน่าเชื่อถือ ไม่ใช่แค่ความคล้าย

หลังค้นด้วย Cosine Similarity แล้ว ระบบให้ "คะแนนเสริม" อีก 2 แบบ ก่อนเลือกอันดับสุดท้าย

🕒 Recency Bonus

เอกสารที่ใหม่กว่าได้คะแนนเสริมสูงสุด +0.08 (ภายใน 1 ปี) แล้วค่อยๆ ลดลงตามอายุเอกสาร

🏛️ Authority Bonus

เอกสารจากแหล่งทางการ เช่น สศก. กรมปศุสัตว์ กรมประมง หรือ NABC ได้คะแนนเสริม +0.04

5.3Coverage Gating — กลไกป้องกันการตอบข้อมูลเท็จ (Anti-Hallucination)

หลังจัดลำดับผลค้นแล้ว ระบบจะแบ่งความมั่นใจออกเป็น 3 ระดับ: เต็ม / บางส่วน / ไม่พบ หากคะแนนสูงสุดต่ำกว่า 0.52 และไม่มีข้อมูลสดช่วยเสริม ระบบจะ ปฏิเสธตอบทันที โดยไม่เรียก LLM สร้างคำตอบ — ป้องกันการเดาคำตอบอย่างเด็ดขาด

ตัวอย่างจริงจากชุดทดสอบระบบ (evals/oae_eval.json)

ผู้ใช้ถามราคาบิตคอยน์วันนี้เท่าไหร่
ระบบตอบข้อมูลที่มีเป็นเรื่องราคาข้าวและปาล์มน้ำมันเท่านั้น ไม่มีข้อมูลราคาบิตคอยน์
ผู้ใช้ถามราคายางพาราปี 2580 จะเป็นเท่าไหร่
ระบบตอบไม่มีข้อมูลคาดการณ์ปี 2580 จึงไม่สามารถตอบคำถามนี้ได้
ผู้ใช้ถามภาวะเกษตร "จังหวัดสมมติบุรี" เป็นอย่างไร
ระบบตอบเอกสารไม่ครอบคลุมจังหวัดนี้ พร้อมแนะนำจังหวัดที่มีข้อมูลจริงแทน

⚠️ ทำไมจุดนี้สำคัญที่สุด

นี่คือความแตกต่างหลักระหว่าง "LLM ตอบเปล่าๆ" กับ "LLM + RAG ที่ออกแบบมาอย่างรอบคอบ" — ระบบทั่วไปมักตอบมั่วอย่างมั่นใจในกรณีเหล่านี้ แต่ระบบนี้เลือก "ไม่ตอบ" แทนการเดา

5.4Tool-Calling — เมื่อ Chatbot กลายเป็น Agent

นอกจากค้นคลังความรู้แบบ RAG แล้ว DeepSeek ยังใช้ Function-Calling ตัดสินใจเองว่าควรเรียก API ภายนอกใดบ้าง แล้วเรียกแบบขนาน (parallel) นำผลรวมเข้าบริบทก่อนตอบ — ทำให้ระบบตอบ "ราคาวันนี้" หรือ "สภาพอากาศตอนนี้" ได้ ซึ่งเอกสารนิ่งไม่มีทาง มีข้อมูลทันเวลา

NABC — ราคาสินค้าเกษตร TMD — สภาพอากาศ RID / DWR — แหล่งน้ำ DOA — ศัตรูพืช CKAN / ThingSpeak — ชุดข้อมูลเปิดอื่น ๆ

5.5ควบคุมต้นทุนและประสบการณ์ผู้ใช้

💬 Response Style Budget

โหมด กระชับ ใช้บริบท 30K / ตอบยาวสุด 768 token — โหมด ละเอียด ใช้บริบท 60K / ตอบยาวสุด 2048 token ปรับตามความต้องการผู้ใช้

⚡ Streaming Response (SSE)

คำตอบทยอยแสดงผลแบบเรียลไทม์ทีละคำ ผ่าน Server-Sent Events ลดความรู้สึก "รอ" ของผู้ใช้ระหว่างที่โมเดลกำลังประมวลผล
